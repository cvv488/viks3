# 1. ФУНКЦИОНАЛ И АЛГОРИТМ
- Запуск: 
    - загрузка конфигурации - настройка логирования 
    - старт сервера
    - старт cli
- Прием соединения (Accept) клиента:
    - ждем аутентификацию с таймаутом
    - при верной аутентификации отправляет ответ, иначе закрывает соединение
    - ждет входящие пакеты
        - при превышении тишины закрывает соединение
        - при запросе статуса от клиента - отправляет ответ
        - при приеме ping - отвечает pong
        - при приеме неподдерживаемого служебного пакета - отвечает командой 0xfe
        - при приеме информационного пакета от этого клиента - отправляет его по назначению - другому клиенту по dest_adr 
        - при приеме спорадического пакета от этого клиента:
          - если dest_adr не 0 отправляет его приемнику (также как информационный пакет)
          - далее если у этого клиента в конфигурации есть список рассылки (spor[]) - отправляет его всем клиентам по этому списку
        - отправка другому клиенту будет если он подключен


# 2. КОНФИГУРАЦИЯ
Состоит из двух частей:
## config.json - настройки приложения, где:
- "port": "45000",     //порт для подключения клиентов
- "max_connections": 10000  //ограничитель на количество подключений
- "wait_reg":10000,  //время ожидания пакета регистрации, мс
- "timeout": 10000,  //таймаут операций чтения/отправки, мс
-  "logmode": "1,0,j"  //режим логирования:
    - [0]: 1-в файл, 2-в Терминал, иначе по умолчанию: в Терминал, json
    - [1]: меняет уровень логирования от Debug (0-DEBUG, 1-INFO, 2-WARN, 3-ERROR, 4-FATAL, 5-PANIC, 6-NO, -1-TRACE)
    - [2]: "j" в json-формате

- "logdir": "logs",  создает файл логов app.log по этому пути, если не указан - пишет в Терминал

- "keep_alive_timeout": 20000,  //таймаут принудительного отключения клиента при тишине, мс
- "debug1": 0  //для отладки:  1-пускать всех при авторизации

## credentials.json - массив конфигураций подключаемых клиентов:
Например:
[
  { "id": 1, "username": "User0001", "password": "Passw0001", "spor":[1001, 1002] },
  { "id": 2, "username": "User0002", "password": "Passw0002" },
  { "id": 1001, "username": "User1001", "password": "Passw1001" },
  { "id": 1002, "username": "User1002", "password": "Passw1002" }
]
где в конфигурации клиента:
- "id" - адрес-идентификатор (int)
- "username" и  "password" - логин с которым сравнивается клиент при авторизации
- "spor" - массив адресов (список рассылки) спорадики этого клиента, т.е. если от этого клиента приходит спорадический пакет он будет отправлен и по этому списку

- "l", "list": вывод списка подключенных клиентов, пример:

    1001: 'Info1001' Conn=[::1]:54561 RunTime=1m53.2435119s Spor:[]
    1002: 'Info1002' Conn=[::1]:54562 RunTime=1m53.1441065s Spor:[]

- "exit", Ctrl+C: выход



# 4. Логирование
- Логировние: Error-ошибки самого приложения, Warning-внешние причины
Пример:

Подключился клиент 1003, всего стало клиентов 3

От клиента 1003 пришел keep-alive, сервер ему ответил (функции 0x28 – Запрос “Keep alive”, 0x29 – ответ на запрос “Keep alive”)
2026-07-30 15:40:00 INF 1003: -> ping
2026-07-30 15:40:00 INF 1003: <- pong

От клиента 1003 пришел запрос статуса клиента 1004, сервер ему ответил 2 (offline)
2026-07-30 15:41:30 INF 1003: -> req_status of 1004
2026-07-30 15:41:30 INF 1003: <- status of 1004 is 2

От клиента 1003 пришел информационный пакет для 1001, сервер отправил его клиенту 1001
2026-07-30 15:40:30 INF 1003: => inf to 1001
2026-07-30 15:40:30 INF 1001: <= inf to 1001

От клиента 1002 пришел спорадический пакет с адресатом 0, у клиента 1002 есть список рассылки spor:[65535,1003]\
2026-07-30 15:48:05 INF 1002: => spor to 0                  //сервер в адрес 0 не отправил
2026-07-30 15:48:05 WRN 1002: Off dest: spor list to 65535  //сервер попытался отправить клиенту 65535, но он offline - не отправил
2026-07-30 15:48:05 INF 1003: <= spor list to 1003          //сервер успешно отправл клиенту 1003, т.к. он online
